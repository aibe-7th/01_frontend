# 실습 1: 게시판 및 댓글 CRUD

프런트엔드에서 Supabase JS SDK를 연동하여 기본적인 데이터베이스 CRUD 및 인증(Auth)을 실습하는 프로젝트입니다.

## 1. 데이터베이스 스키마 작성
Supabase Dashboard -> SQL Editor로 이동하여 아래 쿼리를 붙여넣고 실행(Run)하세요.

```sql
-- 1. 게시글(posts) 테이블 생성
create table posts (
  id bigint generated by default as identity primary key,
  title text not null,
  content text not null,
  created_at timestamp with time zone default now() not null
);

-- 2. 댓글(comments) 테이블 생성 (게시글 삭제 시 관련 댓글 자동 삭제)
create table comments (
  id bigint generated by default as identity primary key,
  post_id bigint references posts(id) on delete cascade not null,
  commenter text not null,
  content text not null,
  created_at timestamp with time zone default now() not null
);
```

## 2. 테이블 스키마 명세 (PK / FK 관계 및 타입)

### A. `posts` 테이블 (게시글)
| 컬럼명 | 데이터 타입 | 제약 조건 | 설명 |
| :--- | :--- | :--- | :--- |
| **`id`** | `bigint` | **`PRIMARY KEY` (기본키, 자동 증가)** | 게시글 고유 식별 ID |
| `title` | `text` | `NOT NULL` | 게시글 제목 |
| `content` | `text` | `NOT NULL` | 게시글 본문 내용 |
| `created_at` | `timestamp with time zone` | `DEFAULT now()`, `NOT NULL` | 게시글 작성 시각 |

### B. `comments` 테이블 (댓글)
| 컬럼명 | 데이터 타입 | 제약 조건 | 설명 |
| :--- | :--- | :--- | :--- |
| **`id`** | `bigint` | **`PRIMARY KEY` (기본키, 자동 증가)** | 댓글 고유 식별 ID |
| `post_id` | `bigint` | **`FOREIGN KEY` (외래키 -> `posts.id`)**, `ON DELETE CASCADE` | 속해 있는 게시글과의 연결 키 |
| `commenter` | `text` | `NOT NULL` | 댓글 작성자 이름 |
| `content` | `text` | `NOT NULL` | 댓글 본문 내용 |
| `created_at` | `timestamp with time zone` | `DEFAULT now()`, `NOT NULL` | 댓글 작성 시각 |

- **관계 설명**: `comments` 테이블의 `post_id` 컬럼은 `posts` 테이블의 `id` 컬럼을 참조하고 있습니다. 게시글(부모)이 삭제되면 이에 종속되어 작성된 댓글(자식) 레코드들도 함께 연쇄 삭제(`ON DELETE CASCADE`)되는 유기적 1:N 관계를 형성합니다.

### 💡 핵심 SQL 키워드 해설

1. **`bigint`**
   - **의미**: 매우 큰 범위의 정수(8바이트 크기)를 저장할 수 있는 데이터 타입입니다.
   - **기능/목적**: 게시글이나 댓글의 고유 ID가 기하급수적으로 늘어나더라도 데이터가 넘치거나 충돌하지 않도록 충분히 큰 용량의 유일 식별 숫자를 보장하기 위해 사용합니다.

2. **`generated by default as identity`**
   - **의미**: PostgreSQL 표준 사양의 자동 증가(Auto-Increment) 속성입니다.
   - **기능/목적**: 레코드가 새로 삽입될 때 개발자가 수동으로 번호를 지정할 필요 없이, 시스템이 1부터 시작해 순차적으로 고유 숫자를 알아서 부여하도록 만듭니다.

3. **`primary key` (기본키)**
   - **의미**: 테이블 안에서 각 행(Row)을 단 하나로 규정하고 유일하게 식별할 수 있는 제약조건입니다.
   - **기능/목적**: 중복 데이터 저장을 원천 차단하며, 특정 게시글의 상세 조회, 수정, 혹은 삭제 처리 시 정확히 타겟팅하고자 하는 그 글 하나만을 확실하게 추적하기 위해 사용합니다.

4. **`references posts(id)` (외래키 / Foreign Key)**
   - **의미**: 한 테이블의 컬럼(`comments.post_id`)이 다른 테이블의 특정 컬럼(`posts.id`)에 실제로 존재하는 값만 가지도록 제한하는 관계 설정 제약조건입니다.
   - **기능/목적**: 존재하지 않는 글에 댓글이 달리는 등 참조 정합성이 깨진 유령 데이터의 발생을 원천 차단하기 위한 필수적인 설계 제약 조건입니다.

5. **`on delete cascade` (연쇄 삭제)**
   - **의미**: 부모 레코드(게시글)가 데이터베이스에서 삭제될 때, 이를 참조하는 자식 레코드(게시글에 달린 댓글들)도 함께 자동 삭제되도록 처리하는 강력한 트리거성 옵션입니다.
   - **기능/목적**: 원본 글이 지워졌을 때 갈 곳을 잃고 DB 용량만 차지하게 되는 고아(Orphan) 데이터를 방지하고, 데이터의 정합성과 무결성을 깔끔하게 관리하기 위한 목적을 지닙니다.

## 3. 주요 실습 내용
- **Auth**: 이메일 가입 및 이메일 로그인/로그아웃 흐름 테스트
- **Posts CRUD**: 게시글 등록(C), 전체 조회(R), 수정(U), 삭제(D)
- **Comments CR**: 특정 게시글에 속한 댓글 작성 및 조회
